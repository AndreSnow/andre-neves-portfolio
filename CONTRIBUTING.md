# Contribuindo

Antes de alterar o projeto, consulte a [documentação](docs/index.md) e as
[convenções de commits](docs/gestao/padroes-de-commit.md). Funcionalidades e
correções seguem a [estratégia de TDD](docs/gestao/qualidade-e-tdd.md).

Toda mudança deve:

- partir de uma branch dedicada;
- manter código, testes e documentação coerentes;
- começar pelo teste que representa o comportamento ou a regressão;
- passar pelo quality gate disponível;
- ser publicada por pull request;
- excluir credenciais, dados pessoais e dados reais de visitantes.
